# Waive

Поиск по каталогу Softline. Первый этап включает потоковый импорт XML, снимки каталога PostgreSQL, полнотекстовый поиск, подбор по артикулу и веб-интерфейс.

## Локальный запуск

1. Скопируйте `.env.example` в `.env` и задайте пароль. В `DATABASE_URL` используйте тот же пароль, кодируя специальные символы по правилам URL.
2. Запустите PostgreSQL, примените миграцию и загрузите каталог:

```sh
docker compose up -d db
docker compose run --rm api alembic upgrade head
docker compose run --rm api python -m app.import_catalog /catalog/Mindbox.xml.gz
docker compose up -d api
```

3. Откройте <http://localhost:8000>. Проверка готовности -- `GET /ready`. Поиск -- `GET /search?q=...`.

Импорт принимает обычный XML и gzip. Он строит снимок и индекс в одной транзакции. При ошибке активный снимок остаётся доступным. Повторная загрузка того же содержимого не создаёт копию. Для локального Compose используется одна роль БД. Перед внешним размещением нужно разделить права сервиса и импорта, настроить HTTPS и проверить нагрузку.

## Итоговая выдача и допродажи

`results` содержит прямые совпадения, `recommendations` -- допродажи. Веб-интерфейс показывает первые 12 найденных семейств и открывает следующие по кнопке «Показать ещё». Параметр API `expanded=true` возвращает все ранжированные семейства среди кандидатов запроса. Без этого параметра `results` по-прежнему содержит до четырёх совпадений. Поле `top4` всегда ограничено четырьмя семействами и используется для оценки. При точном совпадении артикула сохраняется выбранный SKU, а среди остальных вариантов приоритет у доступных предложений с ненулевой ценой. Для товаров без семейства совпадающие поставщик и нормализованное название считаются одним семейством.

При импорте нового снимка поиск строит карту связей по всем заполненным категориям. Правила учитывают назначение дополнения и проверяют применимые поля отдельных товаров. Для ПО это поддерживаемая ОС и лицензионные условия, для оборудования — разъём, интерфейс, формат или явно указанная совместимая модель. Поиск и закупки используют единый подбор по выбранной карточке. В ответе указываются характеристики, по которым подтверждена связь. При недостатке данных показывается статус, объясняющий отсутствие подтверждённого комплекта.

Если подходящие прямые предложения недоступны, доступные аналоги показываются отдельно. При подборе учитываются категория назначения, требования запроса и сравнимые параметры исходной позиции, если она известна. Непрозрачный отсутствующий артикул получает сообщение об отсутствии совпадения. Поле `top4` использует проверенные результаты, аналоги и дополнения и содержит до четырёх семейств.

Поисковая фраза может задавать платформу и её версию, редакцию, тип и срок лицензии, бюджет, наличие, число рабочих мест или пользователей и исключения вроде «без подписки». Каждое требование проверяется на одном предложении. Неуказанное количество и минимальный заказ не подтверждают охват лицензии.

## Подсказки и сравнение

После ввода двух символов поиск предлагает до шести вариантов из доступных предложений. Поиск и автодополнение используют общие варианты названий брендов, например «майкр» для Microsoft. Для этих брендов распознаются и набранные в другой раскладке варианты. Подсказки проверяют точные артикулы и ID, а при отсутствии подходящего семейства с четырёх символов используют названия отдельных товаров. Подсказку можно выбрать мышью или стрелками и Enter. Escape закрывает список.

При опечатке поиск и подсказки используют общий список кандидатов из каталога и словаря брендов. Близкие варианты сравниваются с учётом пропусков, перестановок, клавиатурных соседей и раскладки. Поиск сохраняет введённые версии и артикулы. Если несколько вариантов близки, их можно выбрать в блоке «Возможно, вы имели в виду».

При пустом запросе доступен весь каталог с постраничной загрузкой. Ценовая сортировка оставляет предложения без цены в конце. Популярность учитывает переходы в карточку за 30 дней и исключает демо-сеансы. При равном числе переходов сохраняется исходный порядок. Релевантность при пустом запросе показывает сначала предложения в наличии.

Многоязычная E5-small строит векторы для смыслового поиска и оценивает варианты исправления опечаток. Например, для «адинэсс» модель предлагает AnyDesk. Подсказки и поиск проверяют вариант на одном снимке каталога. Близкие совпадения система исправляет автоматически, когда правила подтверждают выбор модели. Вариант, найденный только моделью, можно выбрать в подсказках или после Enter. Артикулы, версии и остальной текст запроса сохраняются. При недоступности E5 работают правила исправления. Русское «впн» ищет по тому же термину, что и VPN.

Кнопка «В сравнение» добавляет карточку в список из четырёх предложений. Таблицу можно открыть после выбора двух. Выбор сохраняется при переходе к другому запросу. В таблице выделяются отличия цены, наличия и условий лицензии. Если характеристики нет в фиде, отображается «Нет данных в каталоге».

## Подключение смыслового поиска

Для смыслового поиска используем E5-small. Загрузка занимает около 0,49 ГБ без контейнера и зависимостей. Загружайте модель только на согласованном хосте. Том `waive-model-cache` хранит веса отдельно, контейнер читает их без сети. Укажите известную ревизию:

```sh
export MODEL_REVISION=fd1525a9fd15316a2d503bf26ab031a61d056e98
docker volume create waive-model-cache
docker run --rm -e MODEL_REVISION -v waive-model-cache:/models \
  -v "$PWD/inference/download.py:/download.py:ro" python:3.12-slim python /download.py
docker compose -f compose.yaml -f compose.semantic.yaml up -d --build inference api
docker compose -f compose.yaml -f compose.semantic.yaml run --rm api python -m app.index_semantic
```

Перед индексацией дождитесь запуска inference. Проверить режим можно через `GET /search?q=...&semantic=true` и поле `search_mode`. Режим `semantic=false` подходит для сравнения. При отсутствии готового индекса или таймауте модели API обслуживает запрос в текстовом режиме. Новый снимок сразу доступен для текстового поиска. Смысловой режим включается для него после полной индексации. В текущем виде поиск по векторам точный, индекс HNSW можно проверить по мере роста каталога.

## Внешний стенд

На Linux VPS укажите DNS-имя в `WAIVE_HOST`, откройте TCP 80 и 443 и направьте DNS на сервер. Примените миграции, импортируйте XML и подготовьте том модели по шагам выше. Поднимите все три файла Compose:

```sh
docker compose -f compose.yaml -f compose.semantic.yaml -f compose.production.yaml up -d --build
```

База и сервис модели доступны только по внутренней сети Compose. Входящий HTTPS принимает Caddy. Перед выпуском проверьте открытие стенда с другой сети и сохраните резервную копию PostgreSQL вне VPS.

## Оценка и стоимость

Скрипт `scripts/evaluate.py` проверяет попадание целевого семейства или категории на первую позицию и в топ-4. Запуск после прогрева и полной индексации:

```sh
docker compose exec -T api python - < scripts/evaluate.py
```

При запуске с дополнительными файлами Compose передайте их и здесь. Доли отчитываем отдельно для десяти эталонов и пяти смысловых формулировок. Метрики на уровне семейства и категории не заменяют ручную проверку версии и лицензии у каждой карточки.

Для шаблона организаторов фиксируем тариф, дату, объём запросов, задержку и ресурсы. Расчётный сценарий брифа -- 500 запросов в день, 15 000 за 30 дней. Месячная стоимость VPS, БД и хранения делится на расчётное число завершённых поисков. При одном сервере его тариф учитывается один раз. Вызов модели локальный; отдельно измеряем CPU и время разовой индексации, а расходы на внешний модельный API равны нулю.

Для проверки задержки своего стенда используйте:

```sh
python3 scripts/measure.py --mode lexical --requests 1000 --rps 10
python3 scripts/measure.py --mode hybrid --requests 1000 --rps 10
```

Скрипт показывает p50, p95 и p99, фактический RPS, ошибки и частоту перехода в текстовый режим. Параметр `--url` задаёт адрес тестируемого стенда. Черновик формы, порядок записи видео и методика расчёта собраны в [материалах сдачи](docs/submission.md).

### Условия закупки и аналитика

Панель «Фильтры» открывается под строкой поиска. В ней можно выбрать платформу, срок и тип лицензии, наличие и диапазон цены в рублях. Ценовой фильтр учитывает обе границы включительно и пропускает предложения с известной рублёвой ценой. Подсказки извлекают условия лицензии из текста запроса, их применение подтверждает покупатель. Для каждого семейства все выбранные условия проверяются на одном предложении по снимку каталога. В диагностике учитываются найденные поиском семейства. Если ослабление одного фильтра вернёт варианты, интерфейс показывает их число и число семейств без подтверждения этой характеристики.

Для записи запросов из интерфейса и доступа к отчёту задайте длинный случайный `ANALYTICS_TOKEN` в локальном `.env`, выполните `docker compose run --rm api alembic upgrade head` и пересоздайте контейнер API. Откройте `/analytics.html` и введите ключ. Отчёт охватывает последние 30 дней. Чтобы пометить запросы как демонстрационные, откройте поиск с параметром `?demo=true`. Укажите политику удаления событий для конкретного стенда. Например, чтобы хранить только 30 дней, запланируйте в PostgreSQL выполнение `DELETE FROM search_event WHERE created_at < now() - interval '30 days';`. Для показателей переходов используется доля поисков с хотя бы одним кликом соответствующего типа.

### Подбор для компании

Откройте «Закупки для бизнеса» под строкой поиска или перейдите на `/business`. Выберите платформу, срок и тип лицензии в фильтрах и сохраните условия в профиле закупки. Изменение фильтра применяется к текущему запросу. При вводе нового запроса в разделе закупок Waive снова подставляет сохранённые условия. Число рабочих мест хранится как требование для согласования и запроса КП.

Предложения из разных поисков можно добавить в список на согласование. Кнопка «Подобрать комплект» в закупках или «Подобрать дополнения» в обычном поиске появляется у доступных позиций с применимым правилом. Waive проверяет характеристики дополнения на той же версии каталога. Кнопка «Запросить КП» открывает форму с обязательными полями имени, почты, телефона и компании. Профиль и список хранятся в браузере. В отчёте по поиску есть сегменты с профилем и без него.

Для автоматической отправки заполните `QUOTE_RECIPIENT`, `SMTP_HOST`, `SMTP_PORT` и `SMTP_FROM` в серверном `.env`. Если почтовый сервис требует вход, задайте также `SMTP_USERNAME` и `SMTP_PASSWORD`, затем пересоздайте API. Порт 465 использует SMTP через TLS, остальные порты используют STARTTLS. При отсутствии настроек Waive открывает письмо в почтовом приложении пользователя. TXT и CSV доступны из списка на согласование.
