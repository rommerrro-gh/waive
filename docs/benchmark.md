# Сравнение версий поиска Waive

## Набор и режимы

253 запроса на одном снимке каталога. Сравниваются ранняя текстовая реализация Waive (`eb493e9`), текстовый режим перед доработкой (`2104125`), текстовый режим после доработки и текущий гибридный поиск с E5. Ранняя версия -- воспроизводимый baseline. Для сравнения с поиском самого интернет-магазина Softline нужна его выдача по тем же запросам или доступ к поисковому API.

- 120 каталоговых запросов по 40 семействам из 26 категорий. Для каждого семейства взяты точный уникальный артикул, название семейства и название с одной синтетической опечаткой. Три запроса одного семейства связаны.
- 18 вручную сформулированных пользовательских задач. Цель задаётся допустимой категорией каталога. Это прокси релевантности, а не ручная оценка каждой карточки.
- 80 дополнительных опечаток на других семействах и 20 новых формулировок пользовательских задач. Четыре типа опечаток представлены поровну.
- 10 исходных эталонов Softline и пять сценариев, использованных при настройке, показаны отдельно. Они позволяют проверить сохранение поведения.

## Метрики

Hit@1 и Hit@4 показывают число запросов, в которых совпадение есть на первом месте или в первых четырёх. MRR@4 учитывает позицию первого совпадения, при отсутствии оно даёт ноль. Отдельно считаются пустая выдача, ошибки, p50 и p95 задержки, а также запросы, выигранные только одной из сравниваемых систем.

Сравнение парное. Все четыре режима получают одни и те же запросы после прогрева. Порядок вызова меняется. Историческая версия не возвращает категорию; её результаты сопоставляются с категорией общего снимка по ID предложения. Задержка относится к последовательным вызовам на бегунке CI. Нагрузочный прогон хранится отдельно. Отчёт `search-comparison.json` содержит агрегаты по сегментам. Названия, артикулы и идентификаторы из автоматически собранной части остаются в процессе на CI.
